C’est quoi Git ?

Git est un outil de version. Il photographie l’état de tes fichiers à chaque étape importante. Tu peux revenir en arrière, comparer deux versions, et travailler à plusieurs sans écraser le travail des autres.

Ce n’est pas un site web. Git tourne sur ton ordinateur. GitHub, GitLab ou Bitbucket sont seulement des endroits où stocker une copie distante du projet.

  • Dépôt Le dossier du projet, suivi par Git (souvent avec un dossier caché .git).
  • Commit Une sauvegarde nommée : un message + un instantané des fichiers.
  • Branche Une ligne de travail parallèle (ex. une fonctionnalité, un correctif).
  • Remote La copie du projet sur un serveur (GitHub, etc.).

Pourquoi l’utiliser ?

  1. Ne plus perdre son travail. Tu peux retrouver n’importe quelle version précédente.
  2. Comprendre l’historique. Chaque commit raconte ce qui a changé et pourquoi.
  3. Collaborer sans chaos. Chacun travaille sur sa branche, puis on fusionne.
  4. Expérimenter sans peur. Une idée foireuse se jette. Le code stable reste.
  5. Publier proprement. Un remote sert de sauvegarde et de point de partage.

Avant d’utiliser Git

Ne commence pas par git commit. Prépare le terrain.

  1. 1. Installer Git

    Windows : installe Git for Windows. macOS : Xcode Command Line Tools ou Homebrew. Linux : le paquet git de ta distro.

    git --version

  2. 2. Dire qui tu es

    Chaque commit porte un nom et un e-mail. Fais-le une fois sur la machine.

    git config --global user.name "Ton Nom"
git config --global user.email "ton@email.com"

  3. 3. Choisir un éditeur et un dossier propre

    Travaille dans un dossier de projet dédié. Évite de versionner tout ton disque. Ajoute un fichier .gitignore pour exclure secrets, caches et fichiers générés.

  4. 4. Initialiser (ou cloner)

    Projet nouveau : tu crées le dépôt. Projet existant : tu clones la copie distante.

    git init
git clone https://exemple.com/projet.git

Le processus à suivre

Le rythme quotidien, dans l’ordre. Ne saute pas d’étape.

  1. 01 Modifier les fichiers dans l’éditeur
  2. 02 git status — voir ce qui a changé
  3. 03 git add — choisir ce qui entre dans le prochain commit
  4. 04 git commit -m "message clair" — figer l’instantané
  5. 05 git push — envoyer vers le remote (quand il existe)
  6. 06 git pull — récupérer le travail des autres avant de continuer

Règle simple : un commit = une idée. Pas « tout ce que j’ai fait aujourd’hui ».

Les commandes, vite

Commande À quoi ça sert
git status Où tu en es : fichiers modifiés, indexés, non suivis.
git add fichier Prépare un fichier pour le prochain commit. git add . prépare tout le dossier (à utiliser avec prudence).
git commit -m "…" Enregistre l’instantané avec un message.
git log --oneline Liste courte de l’historique.
git diff Montre les changements pas encore indexés.
git branch Liste les branches. git branch nom en crée une.
git switch nom Change de branche (équivalent moderne de checkout).
git merge nom Intègre une branche dans celle où tu te trouves.
git remote -v Affiche les dépôts distants connus.
git push -u origin main Envoie ta branche et mémorise le suivi distant.
git pull Récupère et fusionne les commits distants.
git clone url Copie un dépôt distant en local.

L’utiliser correctement

  • Écris des messages au présent, précis : Corrige le lien du menu, pas fix.
  • Commit souvent, par petits paquets cohérents.
  • Ne commit jamais de mots de passe, clés API ou fichiers .env.
  • Travaille sur une branche pour une fonctionnalité, pas directement sur main dès que le projet grandit.
  • Fais un git status avant chaque commit et chaque push. C’est le réflexe le plus utile.
  • Lis git diff avant de committer : tu vois exactement ce que tu envoies.
  • En cas de doute, ne force pas (--force) sur une branche partagée.
